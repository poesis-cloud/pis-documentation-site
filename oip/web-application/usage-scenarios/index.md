# Usage Scenarios
{: .no_toc }

This section describes how each IT profile uses OIP in practice. Each sub-page covers a specific role's workflows, organized around the governance frameworks and DNA grammar introduced in [General Usage]({% link oip/web-application/general-usage.md %}).

Every profile interacts with the same governed definitions — the difference is *which* definitions they author, *which* they consult, and *which* views they use.

For the full OIP capability catalogue, see **[Features]({% link oip/web-application/features.md %})**.

## Profiles covered

| Profile | Primary activity in OIP |
|---------|------------------------|
| [Enterprise / Solution Architect]({% link oip/web-application/usage-scenarios/architect.md %}) | Define Structures, author Directives, compose ontology stacks, produce architecture deliverables |
| [Developer / Tech Lead]({% link oip/web-application/usage-scenarios/developer.md %}) | Consult specifications, verify code-sourced definitions, check Norm compliance |
| [Project / Product Manager]({% link oip/web-application/usage-scenarios/project-manager.md %}) | Track governance readiness, monitor definition lifecycle state, coordinate deliverables |
| [Operations / SRE Engineer]({% link oip/web-application/usage-scenarios/operations.md %}) | Monitor compliance drift, inspect real-time architecture state, trigger remediation |
| [Security Officer]({% link oip/web-application/usage-scenarios/security-officer.md %}) | Audit regulatory coverage, verify security governance posture, manage security frameworks |
| [Compliance Analyst]({% link oip/web-application/usage-scenarios/compliance-analyst.md %}) | Evaluate regulatory adherence, generate compliance reports, track gap resolution |
| [QA / Test Engineer]({% link oip/web-application/usage-scenarios/qa-engineer.md %}) | Reference quality requirements as test criteria, verify quality governance coverage |
